# Schema & type mapping

This page documents exactly how source structure is translated to Postgres. The
rules live in `transform/types.py` and `transform/ddl.py` and are covered by
`tests/test_types.py`.

## Identifiers

- All target identifiers are lower-cased and sanitized: non-alphanumeric
  characters become `_`, leading digits get an `_` prefix, names longer than 63
  characters are truncated with a short hash suffix so they stay unique.
- Target schema name comes from `naming.schema_template` (default
  `{db}_{schema}`).

## MS SQL → Postgres type map

| SQL Server type | Postgres type | Notes |
| --- | --- | --- |
| `bigint` | `bigint` | |
| `int` | `integer` | |
| `smallint` | `smallint` | |
| `tinyint` | `smallint` | widened — PG has no 1-byte unsigned int |
| `bit` | `boolean` | |
| `decimal(p,s)` / `numeric(p,s)` | `numeric(p,s)` | precision/scale preserved |
| `money` | `numeric(19,4)` | |
| `smallmoney` | `numeric(10,4)` | |
| `float` | `double precision` | |
| `real` | `real` | |
| `date` | `date` | |
| `datetime` / `datetime2` / `smalldatetime` | `timestamp` | no time zone |
| `datetimeoffset` | `timestamptz` | time zone preserved |
| `time` | `time` | |
| `char(n)` / `nchar(n)` | `char(n)` | |
| `varchar(n)` / `nvarchar(n)` | `varchar(n)` | `varchar(max)` → `text` |
| `text` / `ntext` | `text` | |
| `binary` / `varbinary` / `image` | `bytea` | length not preserved |
| `uniqueidentifier` | `uuid` | |
| `xml` | `xml` | |
| `rowversion` / `timestamp` | `bytea` | SQL Server `timestamp` is a row-version |
| `hierarchyid` / `geography` / `geometry` | `text` | no native equivalent; review |
| `sql_variant` | `text` | review |
| _unknown_ | `text` | logged with a note in the report |

Any lossy or approximate mapping records a note that surfaces in the report.

## Postgres → Postgres

Azure PostgreSQL sources already use Postgres types, so column types pass
through unchanged. The extractor embeds length/precision directly
(`character varying(50)` → `varchar(50)`, `numeric(10,2)`), so no remapping is
needed.

## Column defaults

Common SQL Server defaults are translated (outer parentheses are stripped
first):

| SQL Server default | Postgres default |
| --- | --- |
| `(getdate())` | `now()` |
| `(sysdatetime())` | `now()` |
| `(getutcdate())` | `(now() at time zone 'utc')` |
| `(newid())` / `(newsequentialid())` | `gen_random_uuid()` |
| `((0))` | `0` (unwrapped) |

Other default expressions are carried across verbatim and should be reviewed.

## Keys, identity, indexes, foreign keys

- **Primary keys** are emitted inline in `CREATE TABLE`.
- **Identity / auto-increment** columns become
  `GENERATED BY DEFAULT AS IDENTITY`.
- **Non-primary indexes** become `CREATE INDEX` / `CREATE UNIQUE INDEX`, named
  `<table>_<index>` and sanitized.
- **Foreign keys** are applied with `ALTER TABLE … ADD CONSTRAINT` *after* all
  tables in the schema exist. `ON DELETE` actions (`CASCADE`, `SET NULL`,
  `SET DEFAULT`, `NO ACTION`) are carried across. Cross-database references
  cannot be represented in the single-schema model and are skipped + reported.

## What is intentionally not migrated

- Computed columns (review and recreate as generated columns if needed)
- CHECK constraints (add manually where required)
- Triggers (port separately)
- Table partitioning, filegroups, and other storage-level features
- Full-text indexes
